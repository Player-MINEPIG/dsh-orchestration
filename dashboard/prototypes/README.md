# DSH 项目入口交互原型

问题：项目统筹对话与完整任务面板集成进 DSH 后，哪种信息层级更适合桌面和手机？

这是一次性的可交互设计样本，保存在 `codex/project-entry-prototypes` 分支。它模拟 DSH 侧栏和主内容区，不是已安装到官方 DSH 的生产插件。视觉沿用 DSH 的暗色、中性色面板、窄侧栏和聊天输入区；图标采用已安装官方 Web 前端的标识。

## 打开

直接打开 `dsh-projects.prototype.html` 即可，全部内容在一个文件中。也可在仓库根目录运行：

```sh
npm run prototype:projects
```

浏览器访问 `http://127.0.0.1:8127/dsh-projects.prototype.html?variant=A`。

| 版本 | 操作路径 | 适合比较的问题 |
| --- | --- | --- |
| A · 对话优先 | 项目卡片 → 统筹对话 → 按需查看任务 | 是否能把聊天作为日常入口，完整面板只在深入查询时打开？ |
| B · 项目工作台 | 项目概览 → 对话 / 任务 / 资料 | 是否需要项目内平级页面，方便在沟通与审核之间切换？ |
| C · 任务中心优先 | 跨项目任务中心 → 项目详情与关联节点 → 项目对话 → 返回任务中心 | 多项目推进时是否应先关注任务状态，再进入具体项目？ |

底部可以切换版本；`?variant=A|B|C` 可以单独分享；不指定参数时默认打开 C。左右方向键也可切换，输入时不拦截。底部 `…` 显示当前示例状态并提供重置。桌面与手机使用同一个文件，手机详情全屏显示，桌面详情侧边展开。

## 可以体验

- 新建项目：模拟准备项目描述、默认工作区和初始统筹会话。
- 消息：模拟回复并登记一项待开始任务。
- 任务：筛选、详情、执行路由、报告、产物、审核和模拟执行完成。
- 完整面板：项目、任务、执行、报告、产物、里程碑、计划、执行端八类入口；节点图在项目详情内。
- 项目上下文：查看来源和模拟按需注入。
- 整理并继续：审查需要保留的上下文，模拟新会话创建失败或成功。失败不切换原会话，成功后工作区与任务连续。
- 历史统筹会话：查看交接摘要。

仅有当前页面内存中的示例数据，没有存储、后端、真实模型、真实派发或权限修改。完整面板是导航与典型内容的原型，不是现有面板全部管理功能的迁移。memory-manager 显示预期交互，未连接实际服务。

## 验收与结论

真实 Chrome 操作检查了项目进入对话、新建项目、消息登记任务、任务审核、报告导航、完整面板、失败交接及成功交接。在 320 / 390 / 768 / 1280px 下，三版初始页面无文档横向溢出，可见控件未越出视口；横向页面标签可滚动。截图和几何记录位于忽略目录 `.runtime/project-entry-prototypes-20261006/`。

用户偏好 C 的风格，目前以 C 为基础在本分支细化交互；正式插件实现需要另行完成。A、B 保留为比较材料。

### C 的第二轮调整（历史）

- 项目筛选进入独立卡片选择页，显示完整项目描述与进度；选择后返回原页面并保留状态筛选。完整面板也复用该选择页。
- 状态框以边框和 aria-pressed 显示选中状态，再点击已选框恢复全部；移除重复的状态提示标签。
- 修正项目卡容器缺失的 grid/gap，手机卡片间距 18px，桌面 20px。
- 完整面板增加节点图。点击项目展开“项目 → 任务 → 执行 → 报告／产物”，前置任务以虚线连接。执行中、待确认、待开始和已完成使用不同边框，仍保留文字状态。
- 手机纵向排列，桌面横向排列；节点可打开详情，关闭后保留图与页面的滚动位置。审核任务后节点状态同步更新。
- 任务中心进入完整面板后再返回，保留原项目及状态筛选。

本轮在 320 / 390 / 1280px 检查了任务中心、项目选择页和节点图，页面没有横向溢出；还验证了节点状态更新和详情关闭后的滚动位置恢复。记录与截图仍位于同一忽略目录。节点图属于项目任务关系图，物理执行端列表仍在“执行端”页面。

### C 的第三轮调整（当前）

- 首页移除手机项目对话浮窗及桌面对话栏。点击具体项目后，先进入项目详情，再从明确标注项目名称的页面开始对话。
- 项目详情包含目标、工作区、统筹会话、上下文入口与关联节点图。完整面板的项目卡片也进入同一详情；节点图不再是与项目平级的模块。
- 项目对话和项目详情的返回按钮默认回到 C 任务中心，并恢复之前的项目、状态筛选。
- 节点形状区分对象：项目为六边形，任务为圆角矩形，执行为平行四边形，产物为折角文档。文字保留对象类型和状态；待开始节点同时使用虚线边框。
- 状态颜色由同一组 CSS token 定义，覆盖卡片标签、计数、筛选选中边框、看板、节点边框与文字、详情、完整面板和操作提示。项目卡片与项目节点共用状态归纳逻辑。
- 执行完成但尚待审核时，任务和产物为“待确认”，执行记录为“已完成”。执行中的任务，其尚未返回的产物为“待开始”。这是不同对象的状态差异，同一状态的颜色保持一致。

颜色定义、提示颜色和项目状态归纳规则见 [状态颜色规范](STATUS-COLORS.zh-CN.md)。当前仍为内存示例原型。

第三轮已在真实 Chrome 的 320 / 390 / 1280px 视口检查项目选择、项目详情和返回路径，文档无横向溢出，项目卡间距仍为 18px / 20px。验证了任务从执行中转为待确认、再确认完成时，节点图及详情同步更新；实际计算得到的状态文字颜色、SVG 描边和选中边框与规范表一致。执行、产物、执行端页面也核对了状态来源和颜色。私有 HTTPS 预览返回 HTTP 200，内容与本地文件一致，已在部署后的页面重复验证项目对话返回 C。
