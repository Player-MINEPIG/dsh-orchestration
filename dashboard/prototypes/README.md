# DSH 项目入口交互原型

问题：项目统筹对话与完整任务面板集成进 DSH 后，哪种信息层级更适合桌面和手机？

这是一次性的可交互设计样本，保存在 `codex/project-entry-prototypes` 分支。它模拟 DSH 侧栏和主内容区，不是已安装到官方 DSH 的生产插件。视觉沿用 DSH 的暗色、中性色面板、窄侧栏和聊天输入区；图标采用已安装官方 Web 前端的标识。

## 打开

直接打开 `dsh-projects.prototype.html` 即可，全部内容在一个文件中。也可在仓库根目录运行：

```sh
npm run prototype:projects
```

浏览器访问 `http://127.0.0.1:8127/dsh-projects.prototype.html?variant=A`。

| 版本 | 操作路径 | 适合比较的问题 |
| --- | --- | --- |
| A · 对话优先 | 项目卡片 → 统筹对话 → 按需查看任务 | 是否能把聊天作为日常入口，完整面板只在深入查询时打开？ |
| B · 项目工作台 | 项目概览 → 对话 / 任务 / 资料 | 是否需要项目内平级页面，方便在沟通与审核之间切换？ |
| C · 任务中心优先 | 跨项目任务中心 → 任务详情 → 项目对话 | 多项目推进时是否应先关注任务状态，再进入对话？ |

底部可以切换版本；`?variant=A|B|C` 可以单独分享。左右方向键也可切换，输入时不拦截。底部 `…` 显示当前示例状态并提供重置。桌面与手机使用同一个文件，手机详情全屏显示，桌面详情侧边展开。

## 可以体验

- 新建项目：模拟准备项目描述、默认工作区和初始统筹会话。
- 消息：模拟回复并登记一项待开始任务。
- 任务：筛选、详情、执行路由、报告、产物、审核和模拟执行完成。
- 完整面板：项目、任务、执行、报告、产物、里程碑、计划、执行端八类入口。
- 项目上下文：查看来源和模拟按需注入。
- 整理并继续：审查需要保留的上下文，模拟新会话创建失败或成功。失败不切换原会话，成功后工作区与任务连续。
- 历史统筹会话：查看交接摘要。

仅有当前页面内存中的示例数据，没有存储、后端、真实模型、真实派发或权限修改。完整面板是导航与典型内容的原型，不是现有面板全部管理功能的迁移。memory-manager 显示预期交互，未连接实际服务。

## 验收与结论

真实 Chrome 操作检查了项目进入对话、新建项目、消息登记任务、任务审核、报告导航、完整面板、失败交接及成功交接。在 320 / 390 / 768 / 1280px 下，三版初始页面无文档横向溢出，可见控件未越出视口；横向页面标签可滚动。截图和几何记录位于忽略目录 `.runtime/project-entry-prototypes-20261006/`。

当前没有选定方案。待用户比较后记录胜出方案或组合，正式插件实现需要另行完成；原型保留在本分支作为设计依据。
