# DSH 自身 WebUI 的任务插件设置

DSH 自带 WebUI；入口是 `dsh web` 或 `dsh --profile web`。自定义名称的 profile 必须由 Web 模板创建，并且在同一 profile 安装任务插件，才会同时有聊天界面和插件管理入口。只有 base/headless profile 不会自动变成 WebUI。

本包的设置入口位于 **项目与任务 → 任务中心右上角 → 设置**。点击后在主工作区打开宽版页面；顶部显示当前服务的节点 ID，右侧固定显示“任务、项目、完整面板、设置”四项分段导航。旧侧栏“设置 → 任务系统”和插件行配置入口已移除。

页面按“本机与工作区、协作连接、决策模型、运行控制、状态与诊断”排列，所有配置在同一宽版页面，旧模式分支与入口已移除。项目与执行端分别选择父目录；项目任务使用项目目录，普通临时任务统一使用父目录下的 `temporary-tasks`，递归子任务在其内部隔离。已有会话续跑保留原目录。调度端与执行端的决策用途分别绑定 JEV 预设；服务商、模型和思考强度继续由 JEV 管理。

整页只有“本机与工作区”中的“角色”一个设置；协作连接自动沿用，旧连接配置里的独立角色不再决定运行角色。角色切换前校验现有监听、轮询和心跳的兼容性，冲突时保留原配置与草稿。

全部草稿由底部保存栏统一提交；即时变更先保存，需要重启对应插件的变更后保存。多个配置事务可能部分成功，页面会标明失败并保留未完成草稿。任务启动配置、远程连接和每个决策用途保持独立的冲突检查。刷新不覆盖脏草稿，切换到任务中心或模型管理后返回仍保留草稿；刷新整个浏览器会提示未保存修改。

设置始终属于浏览器当前连接的 DSH 服务设备。MBP 的任务中心即使显示中央账本的只读任务，设置页仍修改 MBP。安装升级保留用户当前配置参数、凭据、模型、目录和数据库，不替用户填写或启用连接。

## 可保存的设置

运行字段沿用官方 `configForms` 和 `SettingsFormModel`。只有点 **保存** 才提交；切换页面保留未保存草稿；字段可恢复继承值。保存由官方 Settings/ConfigEditor 校验，并写入当前 profile 的 `cordis.patch.yml`。

| 字段 | 实际作用 |
| --- | --- |
| schedulerEnabled | 规划节点在下一维护轮询接收到期计划；不会取消已排队运行 |
| autoExecute | 本机队列的自动执行接收；不是全节点暂停 |
| maxConcurrent | 本机自动执行器的接收并发上限；节点容量或任务策略可能更严格 |
| healthAlerts | 下一维护轮询是否进行规划端健康告警检查 |
| localHeartbeatIntervalMs | 下一维护轮询是否应记录本地账本心跳；不是远端协调器心跳 |

新安装 bundle 显式关闭 schedulerEnabled 和 autoExecute。页面始终读取当前配置，不静默替换已有 profile 的选择。若 keepAlive=false，自动维护轮询未运行，相关开关不会自行启动一个维护计时器。

## 远程领取独立

关闭 autoExecute 不会停止 `task-remote-execution` 的远程轮询，也不会取消正在运行的任务。已配置的安全重试同样独立。只读区明确显示远端地址、角色、轮询间隔、远程并发以及自动领取状态。

调度端的 **启用任务服务监听** 与执行端连接区的 **启用执行端连接** 各自独立。执行端开关只控制连接调度端、远程接单和心跳，不影响调度端监听或本机任务。角色仅决定可用身份；即使选择双身份，也可只配置并启用其中一侧。未启用侧可留空，不完整草稿保留且不阻塞另一侧保存；开启时才要求该侧完整配置。旧版本暂停曾同时关闭监听，升级保留其实际关闭状态；下一次明确保存连接时固化独立控制语义，不会因升级自动开放原监听。活动或未确认工作仍会阻止需要重建服务的变更。 配置保存会先停止接纳新的后台心跳与轮询，等待已在途的有限心跳和纯发现读取结束，再取得配置保护；心跳失败不阻止切换连接。真实执行、已发出的领取请求与未确认执行回执仍阻止重启；保存失败后恢复原连接的后台活动。

顶部角色草稿立即决定显示范围：调度端显示入站监听、执行端来源与容量；执行端显示上游地址、轮询、并发与心跳；双方角色显示两区。未选角色的区域仍保持挂载，未完成输入不阻塞当前角色保存，也不随当前保存提交；切回对应角色可继续编辑。仅在确有隐藏草稿时显示保留提示。

**启用任务服务监听** 仅控制调度端入站接口，独立于执行端外连。界面分别显示配置勾选与已保存状态；总协作暂停时不会监听。纯调度端不需要填写隐藏的上游地址，就可以保存并启用合法监听。首次连接保存仍保持暂停，由用户完成配置后显式启用。正常态不展示“配置已加载／插件已停用”反向技术布尔，缺失或无法加载时保留异常提示。此页不编辑密钥或登录凭据，已有身份及未知字段保持不变。

## 本机队列与会话摘要

### 地址输入与检验连接

执行端只编辑一组调度端地址/IP、任务协议端口、任务协议路径和 audience，桌面两列、窄屏单列；本机外连来源地址独立保留。保存连接时从这组字段生成协议 URL 与精确目标绑定，不重复填写完整 URL 和目标地址。可信网络使用 HTTP literal IP；已有签名连接保留原 HTTP/HTTPS 协议和路径，只有适用模式显示协议选择。IPv6 自动使用标准方括号，URL 保留显式端口（包括 80）。

读取旧配置时以协议 URL 解析字段，不自动修改配置。旧 URL 与目标绑定不一致时显示提示及“按当前地址同步”；点击后形成草稿，显式保存才统一绑定。保存 JEV、并发或轮询等其他设置不会顺带修正地址。本机来源地址始终沿用用户输入，不从上游 URL 推断。

**检验连接**使用当前草稿，不必保存或启用接单。它用既有认证请求 `executorIdentity`，检查服务是否提供任务协议以及节点是否获准查询身份；不领取任务、不启动心跳或轮询，不证明所有工作区/工具权限或模型 API 均可用。暂停时探测仍保留暂停状态，并复用原远程恢复数据库的出站序列，避免重置防重放状态。正在接单时可检查现有连接，改变目标的草稿须先暂停后检查。成功会显示已确认的节点身份，失败保留具体协议或网络错误。连接检测成功不等于在线；启用状态另显示心跳等待／最近确认时间／发送失败，刷新启动配置可获取新状态。执行端可先完成连接，模型未就绪会明确显示不能执行；可用模型来自该宿主已安装模型目录，已有显式路线或本机模型范围继续收窄。不会更改全局默认模型或伪造可用模型。

本测试部署的任务协议入口是 `http://100.123.230.75:18440`，完整接口路径是 `/dsh-task/v1/commands`。`10000` 是私有 HTTPS WebUI 入口，不能用来接收任务协议。保存错误通过官方 RemoteError 保留业务原因，不再统一显示为 `gateway/internal`。

“打开 DSH 模型设置”是真正的页面跳转按钮，调用官方设置 shell 的共享 store；不保存草稿、不调用模型、不编辑凭据。runtime-13 修复了错误读取 `entry.options.store` 的问题，按官方 slot 合同使用 `entry.store`。入口不可用时单独提示用户点击左侧“模型”，不再误报保存失败。27 项设置测试与真实 MBP 点击跳转已通过。

### 三种决策方式

| 选项 | 实际行为 | 适用情形 |
| --- | --- | --- |
| Rules | 按已配置规则匹配，不调用模型；无匹配规则时放弃判断 | 固定、可明确写出规则的选择 |
| DSH LLM | 调用 DSH 已配置的供应商/模型，校验结构化决策答案 | 非固定任务、自然语言请求；本场景建议使用 |
| Typesafe Jev | 调用 Typesafe 专用决策 API，使用其独立凭据和模型版本 | 已配置并计划使用该专用决策服务 |

决策方式在独立“决策”设置中选择。任务系统分别选择调度端与执行端使用的预设；不同机器的配置仍独立。

本机队列通过独立公开读 API `taskPluginSettings.queue()` 读取有界快照，仅显示 Task/Run 标识、标题、状态、Session/Workspace 标识、读取时间及截断提示。页面首次打开和点击刷新时读取；没有后台领取、执行、取消或数据库写入。读取失败明确显示失败，不能解释为队列为空；刷新失败保留上次样本及其读取时间。

新版后端 `describe()` 顶层提供 schedulerId 和 sessionDecisionEnabled，remote 提供 executorIdentity 和 taskSessionsEnabled。执行端身份只读显示调度端与分配的 executorId；nodeId 明确标为内部 ID，不提供文本编辑器。旧连接沿用原会话协议，界面不扩展 peer grant。

会话决策不需要独立默认工作区；项目上下文与本机已保存目录确定工作目录，决策仅在合法会话中选择新建或复用。决策使用已有 typed-decisions 适配器及其 provider/model 配置，本 GUI 增量没有新增 JEV 协议或凭据输入。角色、会话决策和调度端连接在独立启动表单中编辑；身份仅通过显式查询确认，没有 ID 文本编辑器。启动表单通过公开 startup/saveStartup RPC 保存，原六字段运行表单继续使用官方 SettingsFormModel。

队列及新版会话摘要需要配套后端。旧宿主不具备队列接口时会显示读取失败；缺少新版启动字段时明确提示接口未加载。仅更新浏览器脚本不能激活新的后端接口。

## 独立启动配置保存

启动表单先读取 `startup()` 的条目和值；草稿仅在点击 **保存并重启插件** 后提交。`saveStartup({target, expected, changes})` 只接收指定 task/remote 的严格字段子集；后端使用实际公开 ConfigEditor.edit 合并保存，拒绝旧快照、配置覆盖层与运行中工作。保存后重新读取 startup，并清除旧部署／队列摘要；改变连接不会继承页面之前显示的执行端身份。

Task 允许 role、planningDecisionEnabled、sessionDecisionEnabled；remote 允许 paused、endpoint、audience、pollIntervalMs、concurrency 和受限制的 trustedNetworkTarget。旧连接的 Task 会话迁移使用明确的“保存并重启”操作，无常驻开关，也不扩展 peer grant。身份查询只在点击 **向调度端查询本机执行端 ID** 时调用无参数 RPC，不能指定其他节点。

协作连接为空时可直接填写并点击“保存连接配置”或统一保存，内部通过官方 profile 增量写入接口建立暂停配置。首次保存保持暂停，完成配置后再启用。调度端表单分别保存本机监听地址/端口和执行端来源地址；执行端表单通过同一组地址、端口和路径生成调度端协议 URL 与目标绑定，并独立保存本机来源地址。首次保存不创建密钥；握手之前不会根据昵称生成身份或登记模型。节点卡编辑昵称与允许的来源地址，绑定后的执行端 ID 只读。节点 audience 自动沿用本机调度服务 audience，用户不必重复填写。受信任配对节点采用固定任务协议操作，页面不再要求手工填写 operation/workspace/capability grant；角色、任务/运行归属、会话所有者、租约/fence、执行端实际目录、模型可用性及宿主明确权限继续校验。旧签名身份与显式宿主/任务限制保持。

显式任务或路由的既有工作区授权仍受校验；项目/临时目录规则不绕过这些约束。决策模型使用上面的独立表单，未新增 JEV 协议。

## 独立决策设置与预设

DSH **设置 → 决策** 由 `@dsh-task/typed-decisions` 自己提供，不依赖任务插件或任务数据库。预设可新建、编辑、重命名、设为默认和删除；名称变化不会改变预设 ID。

- Rules 预设选择规则集；规则集支持新建、编辑、移除规则及 JSON 导入导出。导入先形成草稿，点击“保存规则集”才生效。规则集卡片与其内部规则卡片都在原位展开编辑，收起保留草稿。问题 ID 和版本使用普通输入框，路径逐段增删，匹配值选择文本、数字、布尔值、空值、对象或列表，答案按类型显示对应控件，无需手写 JSON。说明和操作按钮之间为 16px；每次保存按规则内容更新版本。无匹配或多条匹配时放弃自动选择。
- DSH LLM 预设选择已有供应商、模型，以及模型实际支持的思考强度；“模型默认”不传思考强度参数。Jev 和已有 compatible 适配器保留原有可编辑的 model/modelVersion/endpoint 内容。凭据在官方“模型”或既有环境引用中管理。
- “检测连接”发起一次小型真实请求，并验证有限候选答案；有正常 API 成本。配置完成不等于连接成功。结果显示检测时间；配置变化后清除旧结果。Rules 显示本地规则校验通过及条数，不声称已连接模型。

模型预设各自拥有配置条目，保留原凭据引用、能力声明、未知字段和其他模型路由；规则预设共享其明确引用的规则集。保存使用公开 ConfigEditor 和 CAS，按正常生命周期重载相关决策插件。有活动任务或模型调用、启动参数覆盖、旧快照或引用未解除时，给出对应失败原因。

任务系统 **选择调度端决策预设** 与 **选择执行端决策预设** 在决策模型区常驻显示，仅选择已有预设，或跟随独立决策页的默认预设。两个角色可使用不同预设；“打开独立决策设置”直接跳转到“决策”页。选择草稿不写配置，点击底部统一保存才生效。原有决策开关仍决定是否使用决策服务，远程暂停设置保留。

其他插件在自己的配置页面显示 `ctx.typedDecisions.presets()` 返回的 ID/名称列表，保存所选 ID，并以 `evaluate({...request, preset: selectedId})` 调用。预设不能和显式 provider/model/reasoningEffort 混用。请求摘要始终校验调用方原始请求，预设选择不会放宽任务候选集、执行端身份或权限。

手机宽度下分段导航和操作按钮自动换行，目录与决策用途改为单列。设置页直接使用主工作区，不依赖宿主的窄版设置侧栏。

决策页沿用任务面板的状态色，不为同一语义另设色值：

| 状态语义 | 颜色 | 决策页中的使用 |
| --- | --- | --- |
| 成功／完成 | `#91b9a4` | 连接检测成功、本地规则校验通过、保存完成提示 |
| 异常／失败 | `#e58f8f` | 连接失败、校验失败、保存失败 |
| 待确认／警告 | `#d3b686` | 需要注意或确认的提示 |
| 执行／当前选中 | `#7ca4ef` | 页签和当前编辑项的选中边框、焦点 |
| 等待／未知 | `#a1a1a1` | 尚未检测、辅助状态说明 |

预设和规则格式、独立插件用法见 `packages/typed-decisions/README.md`。旧的 `decisionSettings` / `saveDecisionSettings` 接口保留给已有调用方，任务页面以预设选择为入口。

## 启动配置和覆盖层

只读区显示当前节点 ID、角色、真实 DB 路径、profile 配置路径、维护设置、租约、工具允许列表与远端连接摘要。地址中的用户信息、query 和 fragment 均不发送到浏览器。密钥内容、环境变量引用和完整 Config 不会进入只读响应。

调度端数据库文件路径、角色和连接字段由本页统一保存，需要时重建受影响插件；目录与运行设置按页面说明即时生效。设备 ID 只读，租约和凭据仍由原运行与安全机制管理。本页不迁移数据库、不创建密钥，也不更改全局运行模型。

配置层顺序是 bundle → profile → Home patch → 命令行 --patch。**config 是整对象替换，不是逐字段合并。** 若 Home 或 CLI 覆写 task-system.config，GUI 保存会由官方宿主拒绝，并且不会落盘。仅从 CLI config 删掉六个可编辑字段仍不能解决。

使用独立测试 profile 时，应把完整 task-system 配置原样放入该 profile，让 profile 拥有这条配置；保留原安全值。task-remote-execution 可继续独立放在既有固定覆盖层里。界面显示命令行覆写是否存在，并在存在 Home patch 时提示其可能覆盖配置；最终拒绝由官方 ConfigEditor 判断。

官方 rc.2 的共享 configForms 在非 loopback 连接使用内存作用域。任务页为这种连接提供专用适配器，通过已认证的公开 Settings.describe/mutate 读取和保存上述六个字段；保存仍使用宿主 revision 校验、字段白名单和 ConfigEditor。它不会改变宿主的 loopback 判定、其他插件的设置页、认证或授权。缺少命名空间、只读宿主和读取失败均禁止保存。

远程访问可使用已有私有网络中的 HTTPS 反向代理，DSH 继续监听 loopback，并配置精确 trustedHosts。首次访问使用运行中的 DSH 打印的登录链接；服务重启会更换该入口 token，已建立的登录 cookie 按宿主规则保留。登录链接属于访问凭据，不应提交到仓库。

任务页在 640px 以下将宿主设置导航改为横向换行，详情和操作区可换行，表单控件保留可触摸高度。规则只作用于正在显示任务页的对话框。实际 VPS 页面已检查 320、390、430、768 和 1280px 视口，记录见仓库手机验收文档；这不等同于物理手机或 Safari 验收。

## 为什么需要浏览器伴生组件

官方 rc.2 的 schema 中虽有 autoGenerate，但官方文档明确说明尚无 shipped client 自动生成页面。仅导出 Config 或通过 schema dump 不会产生 GUI。此实现使用官方插件配置槽位；其六个 volatile 字段保留 Loader 所有的稳定引用，不重启任务服务。

## 2026-10-07：可选决策依赖与独立部署

任务插件可以单独安装。发布包内包含任务路由、会话策略需要的纯 JSON 校验代码；它不依赖决策插件提供这些运行时函数，也不包含决策服务或模型适配器。项目工作区、统筹会话、明确路由与原生执行仍可使用。使用自动执行者决策或工作区／会话决策时，必须另外安装并启用 `@dsh-task/typed-decisions`。

启动配置快照中的 `task.decisionAvailable` 反映当前宿主是否已挂载决策服务。服务缺失或被禁用时，两处决策开关显示为关闭并锁定，旁边提示所需插件名称和“启用后刷新启动配置”；不显示预设选择入口。现有保存配置不被静默改写。后端拒绝开启请求，业务原因码为 `STARTUP_DECISION_REQUIRED`。基本任务配置和任务处理仍可使用。

预设选择框与“保存预设选择”按钮间距为 12px。独立决策页使用宿主设置页滚动；内嵌页面不再产生第二根滚动条，展开／收起编辑表单会同时调整 iframe 高度。

独立部署验收采用两个不同的官方 DSH Web profile，分别只安装一个插件，确认对方包与服务均不存在。决策侧验证规则／预设保存、重载、规则选择和 GUI 校验；任务侧验证工作区与初始会话创建、默认会话策略和原生任务成功结算。执行模型使用测试桩，没有真实 API 请求。证据见 `docs/validation/layout-standalone-plugins-20261007-checks.json`。


调度端可在协作连接区的「调度端 · 执行节点容量」中逐节点修改已登记执行节点的槽位上限（1–32），点击底部统一保存后即时生效。这个设置只修改现有节点容量，不能添加节点、模型、授权或工作区。保存沿用启动表单的并发冲突和活动工作保护。实际并行数同时受执行端远程执行并发及共享工作区串行约束限制，本机自动执行并发为另一独立设置。

项目与临时任务对话的输入框提供“选择调度对话模型”按钮，可从本宿主已配置的供应商与模型目录选择 provider、model 和思考强度。选择按对话持久化，下一条消息生效，保留同一会话；它不改变任务规划的执行端路由。对话正在回复时禁止切换。执行端工具默认跟随 DSH Agent preset（通常为标准模式），并使用其原有权限规则；显式 executionTools 列表保留限制模式。

中断后结果不确定的任务，在对话里显示“核实并确认已停止”。只有核实执行端停止后才可确认，之后可点“重新尝试派发”；确认同步结束旧 Run/Attempt，执行端按同一执行身份对账恢复记录。此流程不自动重复未知效果，也不把重试视为从旧工具调用位置无损续跑。

## 长程任务与主动状态查询

任务没有运行时长预算；旧配置 `executionTimeoutMs` 和旧任务策略 `maxRuntimeMs` 为升级兼容保留，但不再触发停止，也不限制安全重试的等待时间。重试次数、工具权限、租约和取消规则继续生效。

任务卡片、列表和详情显示已运行时间，按秒更新，已结束运行显示固定时长。运行中的任务详情提供 **请求运行状态**：请求在下次租约续期到达执行端，通常约 20 秒内回报；面板区分等待回报与已收到的回报及时间。执行端读取当前会话阶段、已完成步骤、工具调用次数与最近公开说明，不调用额外模型、不重新派发任务。用户可随时通过原有取消操作要求停止；取消确认仍等待执行端停止后回执。

## 手机对话滚动与恢复提醒

对话轮询仅更新变化的消息与状态，不因节点心跳重建整个聊天界面。阅读历史时保留可见消息的位置；已在底部时跟随新消息；输入框和正在输入的草稿保留。恢复提示使用紧凑布局和实色按钮，关闭只在当前页面隐藏当前运行的提示，不执行取消、重试或标记已处理；从任务详情仍可操作，新运行可重新出现提醒。

没有 `result` 报告表示调度账本尚无完成证据，不能据此断言执行端未完成。现有统筹对话只能查询账本及规划任务，尚未提供向执行端原会话发送普通消息或补取旧会话回执的工具；用户仅询问结果或明确要求不重跑时，不应规划重试。心跳、连通性检查、读取已有账本无需创建 Run/Attempt。


对话输入框的“对话对象”可选择调度者或任务已绑定的执行端原会话。
项目对话列出项目下任务的会话，临时任务对话列出该任务的会话。
发给执行端的消息以及执行端的回复带有 ↪ 标记、节点名称；发送消息显示等待、已回复或未确认状态。
该入口直接复用现有端间连接，不调用调度者模型、不创建 Run/Attempt、不修改任务完成状态。
原会话忙碌时排队。执行端须升级并由调度端为已有 peer 授予 sessionMessages 和 sessionMessageReply 操作。


### 人工确认与补交材料

任务详情在手机上占满可用屏幕，桌面可切换全屏；轮询更新保留同一详情的滚动位置。
原“标记已处理”和独立“取消任务”按钮合并为“人工确认”：

- **已完成，要求补齐材料**：人工确认目标完成，显示“已完成 · 待补材料”，通过原执行会话请求已有结果，不创建 Run/Attempt。该会话后续回复另存为待核对的补交材料，旧执行结论不改写。
- **已完成，不要求补齐材料**：直接归入已完成；也可用于材料核对完成后关闭补交通道。关闭后在途消息仍保留聊天历史，但不再纳入材料。
- **取消任务**：沿用取消流程，正在执行的任务先请求停止。

仍在执行或结果不确定时，不能人工确认完成；需先停止并核实。补交要求原执行存在可绑定的会话；旧消息和其他会话回复不会追溯纳入。补交支持文本内容与文件路径，不代表跨机器复制文件，也不把模型回复自动视为材料齐全；核对后由用户结束补交。


补交反馈会随持久消息与报告更新：已请求补交、请求失败/回复未确认、已收到材料待核对。最新补交内容替换“执行报告”区域的当前展示，先前报告折叠保留在同一区域；不会改写原 Run/Attempt 的执行结果。报告正文使用 Markdown 渲染，原始 HTML 作为文本显示，外部图片不自动加载。

## 本机实例身份、节点配对与数据库

执行端只读展示稳定本机实例 ID（nodeId）。既有非空 ID 原样保留；旧缺省身份保留 local 并首次持久化；全新实例生成 node-UUID，身份文件放在当前 profile 的 task-system/device-identity.json，独立于可切换的任务数据库。已有身份文件优先于目标库，因此切库、重启或更换调度端不会改变 ID。调度端返回的 executorId 仅在诊断中称为“调度端登记号”，与设备身份分开。

双方都必须明确配置：执行端保存调度端地址、audience 与本机来源，调度端保存允许的来源 IP 与节点昵称。只允许该可信来源发来的首次合法 heartbeat/executorIdentity 建立配对；格式、时间窗、来源、audience 和协议防重放通过后才持久绑定真实 nodeId。陌生来源拒绝；已绑定来源改报另一 ID、同一 ID 占用多个来源或与调度端本机 ID 碰撞时拒绝，须显式移除重加。昵称从不生成或修改身份。

首次握手幂等登记节点，心跳公布该设备当前真实可用的模型目录；没有模型时可以已连接但执行未就绪。新 Task 会话采用官方 PTC preset 和宿主默认工具，包含 run_code 传输；内部调用仍通过宿主、任务工具范围、归属、取消与租约校验。没有 PTC 的宿主明确报告未就绪；旧会话续跑沿用记录的 preset，不强制改成新模式。

节点卡的“检测”读取已绑定 ID、最近已认证心跳、过期状态与模型登记，不假称反向探测无监听执行端。未保存的节点草稿明确说明尚未检测；编辑使旧检测证据失效。卡底左侧“移除执行端节点”、右侧“检测”。移除即撤销来源接入并持久解绑，暂停状态也生效；允许移除最后一个节点，监听保持时拒绝所有来源，历史节点停用而不删除任务记录。

调度端/both 可编辑 SQLite 数据库绝对文件路径。保存前只读预检已存在目标的 schema/authority/完整性及路径可用性，不迁移或覆盖它；不存在的目标由用户明确保存后创建新账本，拥有自己的调度端身份。切换会重建 task 与依赖 remote 服务，旧库保留；旧默认工作区绑定在切换时清除，避免把原库对象引用带入新库。失败回滚配置并重新加载原运行服务。执行端单身份隐藏该设置并保留未提交路径草稿。

## 节点默认执行模型与按需目录

调度端的执行端节点卡片可设置此节点的默认执行模型及思考强度，以真实执行端 ID 绑定；昵称不参与身份或策略索引。未设置时使用 `deepseek-official/deepseek-flash` 的 `high`。这不会修改 DSH 全局模型或 JEV 决策模型。用户明确指定的执行模型优先，不能使用时显示需处理，不静默替换。仅在最新完整目录确认节点默认值不可用时，未领取且没有任何 Attempt 的默认来源执行请求可回退 Flash/high，并记录原因；已经开始、结果未确认或显式指定的执行不会改模型。

模型目录通过执行端既有出站连接按需获取，不随心跳发送，也不再受旧 `nativeRoutes` 或 `localNode.models` 两模型掩码限制。关闭执行端连接时不拉目录，任务轮询为 0 仍可响应目录请求。目录超时、离线或部分失败保留最后成功目录及默认值；部分成功的新鲜条目可作为模型存在的证据，缺项不能作为模型消失的证据。原生 DSH 与官方后端保持不同身份及各自真实权限。

保存节点默认模型时，调度端使用当前新鲜目录确认用户选择的精确模型与档位。目录过期时有界刷新，不要求重新选择，也不因目录版本变化替换草稿。刷新失败或部分目录未确认所选项时保留草稿；仅完整新鲜目录缺项才明确报告该选择不可用。并发修改默认值或调度端身份变化仍拒绝保存。

公共 `task_plan` 的 `provider/model/reasoningEffort` 仍指决策调用；实际工作模型使用独立 `executionModel` 对象。调用者应将用户明确的模型要求放入该对象，未指定就省略。`task_run` 选择节点后可使用其默认；`action=repair` 带原 `runId` 与 `expectedActionVersion` 可修复未领取请求，保留原 ID，不新增 Attempt。定时任务必须绑定项目。

临时任务的执行上下文由权威调度端生成，无需调用方创建规划会话或手填工作区。执行端缺目录、显式模型不可用或明确工作区绑定缺失时，任务中心及查询工具显示原因和下一步。正常离线、容量满和等待目录属于等待状态；恢复配置后继续原请求，不把等待伪造为执行失败。
