# DSH 宿主中的任务界面与设置

插件注册「项目与任务」主面板、完整任务设置、会话任务页签及项目命令反馈；项目与工作流 iframe 通过宿主会话桥调用公开 RPC。旧决策控制台已移除，模型配置入口是独立 JEV 设置。

## 设置范围

设置页按本机与工作区、协作连接、观察归并、运行控制、状态与诊断组织；区域按本机实际能力呈现。页面始终显示当前服务设备，中央任务的观察范围不改变设置所属设备。

修改先形成草稿，由统一保存条提交。即时设置与需重启插件的设置分别标明；部分失败保留未完成草稿。正在运行或尚未确认的执行会阻止重启类变更。普通运行参数使用官方 `SettingsFormModel`，启动与连接设置使用公开 RPC、预期 revision/快照及 `ConfigEditor`。Home 或命令行覆盖层、旧快照与权限不足会拒绝保存，不静默改写部署。

节点身份、调度端分配的执行端 ID、执行状态和凭据保持只读。目录选择与本机工作区授权保留已有权限检查；调度端无法借输入路径扩展执行端文件权限。远程领取、心跳与本机自动执行独立配置；关闭一个开关不表示停止既有任务。

观察归并仅选择 JEV 已有预设；提供商、模型、思考强度与 API 凭据在 JEV/DSH 模型服务中管理。正式派发和工作区/会话归属不调用 JEV 来扩大权限。旧绑定仅作为兼容数据读取。

## 阅读和交互

任务结果、待确认、已完成、已验收、执行失败、部分完成与结果待核实保持区别。任务详情按原执行来源展示报告、修订、材料及会话引用；打开历史不会重新派发。确认本机提醒仅改变提醒状态，不伪造原执行结果。

项目原生会话使用官方宿主会话、工作区与授权；插件叠层只承载项目范围和连接反馈。切换页面、主题或刷新读取不丢弃已有会话和草稿。会话任务页签只读取当前来源关联的记录。

## 验证与部署

`npm run test:ui` 验证设置、权限和视图契约；`npm run test:browser` 覆盖真实 React 与独立官方宿主的保存、失败、会话、提醒及响应布局。`npm run test:distribution` 验证安装、启动、移除与数据保留。具体命令见[CI](../../../docs/CI.md)，设备更新见[开发流程](../../../docs/DEVELOPMENT.md)。历史验证记录不代表当前设备状态。
