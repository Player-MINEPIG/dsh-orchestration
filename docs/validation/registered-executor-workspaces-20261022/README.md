The reported “only production, missing existing projects” came from a design gap in 0.2.44: the MBP official registry contained seven existing directories, but task discovery advertised only the configured `prod-mbp` directory plus separately persisted per-directory grants. The seven native directories therefore never reached AWS. The project page also hid its directory guidance whenever any configured workspace was ready.

For a trusted-network coordinator connection, physically valid native registry directories now supply the same path-bound workspace IDs to the local catalog, heartbeat and final execution check. This does not insert a bulk local-grant record or save any project binding. A project explicitly selecting a directory pins its ID to the Run. Registry deletion or a changed path invalidates the old ID. Explicitly disabled local entries remain disabled, including after registry path changes, until the owner enables them. Configuration bindings retain their own allowedRoot and take precedence for the same path. Signed connections do not auto-adopt native directories, and static peer allowlists still filter announcements. No arbitrary scheduler-supplied path is accepted.

The local owner page distinguishes native-registry availability, configuration-owned authorization and explicit disable state. A physically available disabled workspace can be enabled again; missing directories remain unavailable. Project settings always show the reported usable count and the exact execution-host settings path for checking missing directories, even when `production` is present.
