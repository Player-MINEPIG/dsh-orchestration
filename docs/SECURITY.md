# Security boundaries

Task intent, model advice, execution authority, observed evidence and delivery are separate facts. Models never issue credentials, add peers or grant workspace access. The default host configuration has no workload tools, no automatic execution and no live Feishu connection.

## Trust and identity

Peer public keys, operation grants, node capabilities, workspace roots and installed provider code are operator-controlled. Each signed request binds node, key ID, audience, expiry, sequence, nonce, operation and payload. Payloads cannot supply a substitute actor or arbitrary shell/cwd. A peer can inspect/claim/renew/settle only its assigned node and configured workspace scopes. Peer cancellation is also node-bound; coordinator-wide cancellation uses the trusted local operator interface.

TLS is required for non-loopback HTTP. Literal local loopback is accepted for isolated development; forwarded headers never grant local trust. The DSH HTTP carrier itself does not imply authentication or TLS. No production credentials are generated by installation.

## Execution

The TaskLedger is one transaction owner. Inputs and idempotency receipts commit atomically. Same ID plus different payload fails. Attempts carry explicit node and fencing identity; ordinary stale/expired claims cannot settle. A trusted local recovery path can commit an exact native terminal result recorded by the independent FULL/WAL journal before the lease expired, only after session flush and handle disposal. Recovery rechecks the same current attempt, node, fence, execution owner and session, rejects cancellation/replacement, and has a 24-hour bound. It is not a peer operation or model tool. Before effects, a compare-and-set binds the attempt to one execution instance. Separate executor journals sharing a node identity cannot both start the same claim; subsequent writes require that execution identity. This prevents accidental duplicated workers, not a malicious process already holding the trusted node's credentials. Native tools bind the exact owning DSH agent to its attempt; final assistant text and idle cannot substitute for a structured result.

A cancellation request retains execution resources until a correlated acknowledgment after actual provider quiescence. An expired or interrupted attempt becomes uncertain and holds resources until explicit reconciliation. Restart does not re-run a potentially effective prompt. A new authorized run preserves the previous run, evidence and result history.

Task policy can only narrow parent node/workspace/tool lists; an empty list means deny all. Invalid/null policy fields are rejected. Runtime deadlines do not reset when a native attempt resumes. Delegated tasks have explicit parent identity and depth limits.

Known native file tools check canonical workspace paths and reject symlink components and permission escalation. The workspace must be owned by a trusted operator; portable checks do not provide an OS sandbox against a hostile local process racing filesystem updates. Shell/custom/search execution is denied by default and requires explicit broader trusted configuration. A working directory alone is not confinement.

## History and artifacts

Task/run/session identity is not report identity. Distinct submissions and corrections append to history even when text matches. Exact transport replays do not create new effects. Artifact content is immutable; digest and byte length are checked again when a result references finalized artifacts. A mutable latest-summary view never replaces original history.

Legacy import reads a selected source database without executing its code. It imports historical evidence as observations; it never activates old leases, schedules, credentials or pending dispatch. Reports may contain private content and must remain in authorized storage.

## Channels and decisions

Feishu uses the official SDK and explicit allowed users/chats. Incoming records persist before ACK. Task controls additionally require configured operators and correlated current task/run/message identities. Repeated callbacks cannot repeat a control effect. An unknown send result is held; an operator must reconcile actual provider evidence before any further action. A sent notification does not change a failed task to success.

Typed decisions validate finite candidates and versioned schemas. Ordinary structured output does not imply calibrated probabilities; compatible logits/hidden-state providers declare their actual evidence and calibration. Receipts distinguish configured model pins from provider-reported versions where supported. Decisions persist before task effects and must pass current catalog and deterministic policy checks.

## Read surfaces

The WebUI is read-only by default, with explicit host authorization when mounted remotely. It uses the same TaskLedger. A static private export is a timestamped view, not live synchronization. Private runtime databases, actual task exports and deployment identities are excluded from Git/npm.

## Validation limits

Disposable keys and fixture directories are used only for isolated tests. Live Feishu/Jev/model quality, arbitrary hardware networks, Windows GUI/session behavior and production installation require separate authorized acceptance. Browser rendering checks and GitHub CI may be blocked independently of local tests; see validation receipts rather than inferring those stages passed.

## Finite payloads and extension trust

The core command boundary accepts at most 2,000,000 canonical JSON characters per operation. Transport byte caps are independent (64 KiB requests and 128 KiB responses by default, explicit maximum 16 MiB); increasing a transport cap does not remove the core bound. Large historical migrations must be split into coherent bounded imports. Registered semantic validators and source adapters are reviewed host code, with synchronous cloned inputs; a model can select an allowed template but cannot register a validator. Native source preparation is checked before the durable result handoff, while the authority separately validates the result contract. Trusted executor credentials remain an authority boundary.

Task curation hides dismissed items from ordinary task/history queries without disabling independent health alerts or pending runtime permission requests. Those controls remain visible until explicitly resolved or expired.

## Automatic recovery policy

Transient native failures can resume the same persisted DSH session with finite backoff and the original runtime budget. The default proof permits no tool dispatch. An operator may additionally list reviewed `safeRetry.resumableTools`; every call must then have a matching successful result in the complete live event interval, followed by a successful session flush and disposal of the original owned handle. The run retains name/argument fingerprints across retry fences, and the next attempt rejects an exact repeated completed invocation. The continuation asks the agent to use persisted results rather than resending the original task.

This guard does not prove that a custom shell command stopped detached processes, or that different arguments cannot cause the same external effect. Only explicitly reviewed tools whose returned result closes their effects belong in this allowlist. Partial/failed/missing tool results, unreviewed tools, uncertain ownership and interrupted evidence remain uncertain and need reconciliation. The old broad disconnect heuristic is intentionally replaced by these explicit configurable recovery conditions; arbitrary external effects are not claimed to be exactly once.
