# 私有阶段交付评阅指南

这次交付围绕“可配置的任务管理系统”重构。两套核心插件分别承担通用类型化决策、任务账本与安全远端执行；飞书入口是独立可选适配器；任务模板、来源适配器和 WebUI 复用同一 Task/Run/Report 契约，不另建第二套任务系统。

## 从哪里开始

1. `docs/PARITY.md`：64 个来源支持的功能结果、原实现位置、新实现与验收边界
2. `docs/architecture/comparison.html`：旧架构与当前架构；同目录还包含任务与报告生命周期、来源及验证记录
3. `docs/dsh-integration.md`：固定 DSH 0.2.0-rc.2 的安装、角色配置与实际运行步骤
4. `examples/legacy-task-pack/README.md`：旧日报、游戏日报、临时工作回顾、配额与诊断的可配置迁移
5. `docs/SECURITY.md`、`docs/MIGRATION.md`：权限、恢复、历史数据迁移和生产接入边界
6. `dashboard/README.md`：挂载同一账本的只读 WebUI，支持移动布局与明确时间截点的私有导出

## 核心行为

- 一个稳定任务保留多次执行、不同 session、多份报告、修订与产物。传输重放不会制造重复效果，语义上新的报告不会被去重掉
- 日报和游戏日报是可配置任务类型；新建项目指实际工作区。查看方式可替换，不绑定旧 Bitable 或数据库浏览服务
- 插件挂在 DSH 宿主中，由宿主及外部监督程序负责运行生命周期。插件提供配置、加载、资源回收与恢复
- 观察记录默认只收录；明确的新请求才进入执行。排除收录独立于取消、完成，恢复收录也保留原历史
- 模型可以提出任务、执行端、模型、推理强度、工作区及上报建议。确定性权限检查与操作者配置决定是否落实
- 原生结果必须有因果绑定、停止执行与持久化证据。消息送达、报告有效、业务结果、任务终态分别记录
- 自动恢复保留同 session、有界退避与原时间预算。默认只允许零工具执行；明确配置的可恢复工具还需完整成功结果及重放指纹检查。未知副作用不自动重派

## 验收阅读方式

本地测试使用真实 SQLite、签名协议、TLS 环回、DSH Loader/AgentLoop/SessionStore 和正式 CLI；模型、外部网络响应及旧数据使用明确的合成输入。实际跨设备网络、真实 Feishu/Jev/模型质量、Windows 游戏数据和完整自动日报需要在授权的真实环境继续验收。旧八月修复后的下一次完整自动根日报，也没有历史证据可追认成功。

具体测试数量、固定代码版本、包摘要及执行时间以本次验证清单为准。图表的严格结构检查、静态图像检查和真实浏览器检查分别记录。远端发布与精确推送版本的 CI 状态见仓库交付记录。公开仓库、npm 与 awesome-list 提交没有执行。
