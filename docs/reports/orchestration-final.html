技术决定

决定原因与边界
skill 指导，工具约束模型组织任务，插件固定项目身份、执行授权和 requestId。工具响应中的真实状态决定是否已经执行，不能由模型自报项目权限。
中央仍是一份业务数据库协作绑定、项目、任务与回执进入既有中央账本；本机只保留绑定、会话及重试记录。中央离线不会代建另一个中央。
恢复及幂等写入以稳定 requestId 重试。同节点客户端共享 recovery store；不同连接仍可能乱序，只有明确的 HTTP 409 OUT_OF_ORDER 才自动重试，总共最多三次，保持命令和业务内容不变。网络结果未知不自动重放。
完整可执行路线project_nodes.routes 公开节点获准且 ready 的工作区 ID，不公开路径或凭据；agent 原样传入完整路线。显式路线缺 workspaceId 时在创建任务前拒绝；宿主仍验证工作区和执行权限。
执行端原面板能看到本机发起的协作项目，即使尚无 Run；项目派往其他节点的任务也保留在本项目视图。仍只读，中央鉴权裁剪。
宿主管理 CLI插件使用认证心跳公布的可用执行路线；模型、推理强度与实际运行证据分开记录。插件不锁 CLI 安装版本、不向 agent 暴露 CLI 路径或凭据。
完成与复核分离project_finish 只提交待复核；有活动执行或未解决任务时拒绝。后续新增工作重新进入进行中。

职责实现与理由
派发协议插件提供 task_delegate 包装：固定父 Run、租约、权限继承及展示建议，再调用官方执行设施。官方生命周期不被另写的会话管理器替代。
递归展示每个子任务保留真实 Task / Run / Attempt；独立交付显示任务卡，小步骤折叠在父 Run 内。显式选择优先，其次复杂度建议，默认保留任务条目。当前展示建议未额外触发 JEV 模型决策。
结果边界执行成功、来源声称完成、中央审核通过分别记录。Codex 成功结果仍等待用户审核；父任务结算检查子树静止，避免派出去就声称整个项目完成。
可见范围中央按已认证节点生成执行端快照。共享一个项目不会自动带出其他节点的无关兄弟任务。查看中央全部项目需要进入原有中央面板并使用其登录权限。

为什么插件不锁 CLI 版本

CLI 安装、升级和选择属于执行端宿主。插件接收可选 officialBackends[].cliPath；未指定时使用官方 Provider 自带路径。版本号仅作为诊断证据记录，不是准入白名单，也没有仓库级强制 Codex 版本覆盖。

插件仍需验证它承诺的执行条件：实际模型和思考强度、权限策略、隔离模式以及允许的工具通道。不能满足时明确拒绝，不静默换模型。面板分别标明计划路线与同进程握手确认的模型，并显示产品线程和执行端运行时版本。
